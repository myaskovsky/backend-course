## 1) Трансформация изображений

### 1.1 Общее

**Назначение:** конвертация изображений между форматами PNG, JPEG, SVG.

**Пользователи/роли:**

- Только аутентифицированный пользователь.

**Контекст/предпосылки:**

- Авторизация через access JWT (cookie).
- Доступ к endpoint’у только после аутентификации.

**Зависимости/связанные настройки:**

- Библиотеки для работы с растровыми изображениями (PNG/JPEG) и SVG.
- Лимиты размера файлов: устанавливаются администратором в конфигурации приложения отдельно для каждого входного формата (PNG, JPEG, SVG).
- Максимальные размеры (ширина/высота) выходного растрового изображения при растеризации SVG: устанавливаются администратором в конфигурации или хардкодятся (простое решение).
- Параметры растеризации SVG: фон по умолчанию — `#ffffff`.

### 1.2 Сценарии

1. **PNG → JPEG:** пользователь загружает PNG, получает JPEG.
2. **JPEG → PNG:** пользователь загружает JPEG, получает PNG.
3. **SVG → PNG:** пользователь загружает SVG, получает PNG (растеризация).
4. **SVG → JPEG:** пользователь загружает SVG, получает JPEG (растеризация).
5. **Список поддерживаемых форматов:** клиент запрашивает доступные направления конвертации.

**Постоянное ограничение:**

- Конвертация PNG/JPEG → SVG (векторизация) не поддерживается.

### 1.3 Контракт

#### 1.3.1 Конвертация изображения

**Операция:** `POST /api/images/convert`

**Входные данные (multipart/form-data):**

- `file: binary` — исходное изображение (PNG, JPEG или SVG).
- `targetFormat: string` — целевой формат: `png` | `jpeg` | `svg`.
- `options: object` (опционально):
    - `quality: number` — качество JPEG (1–100), если целевой формат `jpeg`.
    - `width: number` — ширина выходного изображения для SVG → растровый. Если не указана — используется intrinsic размер SVG или дефолтное значение.
    - `height: number` — высота выходного изображения для SVG → растровый. Если не указана — используется intrinsic размер SVG или дефолтное значение.
    - `background: string` — цвет фона при растеризации SVG. По умолчанию: `#ffffff`.

**Проверки/валидация:**

- `file` обязателен, не пустой.
- Размер файла не превышает лимит для исходного формата (PNG, JPEG, SVG).
- `targetFormat` обязателен и входит в `png` | `jpeg` | `svg`.
- Исходный формат определяется по содержимому/расширению и должен быть PNG, JPEG или SVG.
- Пара исходный → целевой должна быть поддерживаемой:
    - `png → jpeg`
    - `jpeg → png`
    - `svg → png`
    - `svg → jpeg`
- Файл должен быть валидным изображением соответствующего формата.
- SVG должен быть безопасным (без скриптов, внешних сущностей).
- Для SVG → растровый: итоговые размеры (`width`, `height`) не должны превышать максимальные значения, заданные в конфигурации/хардкоде.
- `quality` (если указан) — целое число от 1 до 100.

**Логика/шаги:**

1. Принять файл и параметры.
2. Определить исходный формат.
3. Проверить размер по лимиту исходного формата.
4. Проверить поддержку направления конвертации.
5. Для растровых (PNG/JPEG): декодировать изображение; при необходимости применить параметры (quality для JPEG).
6. Для SVG → растровый: выполнить растеризацию с учётом `width`, `height`, `background`; проверить итоговые размеры на соответствие максимальным.
7. Закодировать результат в целевой формат.
8. Вернуть результат как потоковый файл.

**Ответы:**

- **200 OK:** изображение в целевом формате, заголовки `Content-Type` (например `image/png`, `image/jpeg`, `image/svg+xml`) и `Content-Disposition: attachment; filename="converted.<ext>"`.
- **400 Bad Request:** невалидное изображение, неподдерживаемое направление, некорректные параметры, превышение максимальных размеров.
- **413 Payload Too Large:** превышен лимит размера для исходного формата.
- **415 Unsupported Media Type:** неподдерживаемый формат файла.
- **401 Unauthorized:** неаутентифицированный запрос.

#### 1.3.2 Список поддерживаемых форматов

**Операция:** `GET /api/images/convert/formats`

**Ответ:**

- **200 OK:** массив объектов `{ source: string, target: string[] }`:
    - `{ source: "png link", target: ["jpeg"] }`
    - `{ source: "jpeg link", target: ["png"] }`
    - `{ source: "svg link", target: ["png", "jpeg"] }`

**Проверки:**

- Авторизация (JWT валиден).

### 1.4 Ошибки и ограничения

- Неподдерживаемое направление конвертации (PNG/JPEG → SVG запрещено навсегда).
- Некорректный или повреждённый файл изображения.
- Превышение лимита размера (зависит от исходного формата, задаётся администратором).
- Превышение максимальных размеров при растеризации SVG (ширина/высота).
- Ошибки растеризации SVG (некорректные размеры, отсутствие intrinsic size, сложные/неподдерживаемые SVG-фичи).
- SVG с небезопасным содержимым (скрипты, внешние ссылки) — отклонить.
- Защита от декомпрессионных бомб (очень большие размеры при маленьком файле).

### 1.5 Аудит/логи

- Логировать: `userId`, `sourceFormat`, `targetFormat`, `fileSize`, результат (`success` / `error` + код), длительность.
- Не логировать содержимое изображения.

### 1.6 Нефункциональные требования

- **Безопасность:** проверка SVG на отсутствие активного содержимого; запрет внешних ресурсов; ограничение количества пикселей/размера при декодировании; защита от decompression bomb.
- **Производительность:** потоковая обработка для больших изображений; таймаут на конвертацию (например, 30 сек); ограничение максимальных размеров (ширина/высота) для растеризации, заданных администратором или хардкодом.
- **Надёжность:** корректная обработка альфа-канала (PNG), атомарность ответа.
